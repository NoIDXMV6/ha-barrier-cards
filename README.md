# Карточки шлагбаумов для Home Assistant (А.М.Видео + ЕГДС)

> ⭐ **Эволюция проекта:** автоматическое открытие шлагбаума по
> распознаванию вашей машины (без номеров) и калитки по лицам —
> в репозитории **[hha-smart-access](https://github.com/NoIDXMV6/ha-smart-access)**.
> Там же — обновлённые карточки с кнопкой **«Обучить»**.

Готовые карточки Lovelace для панелей Home Assistant к интеграциям
[amvideo-ha](https://github.com/NoIDXMV6/amvideo-ha) (А.М.Видео)
и [egds-ha](https://github.com/NoIDXMV6/egds-ha) (ЕГДС):

- живое видео камеры шлагбаума прямо на карточке;
- кнопка «Открыть шлагбаум» поверх видео;
- кнопка «во весь экран» — диалог с живым видео;
- опционально: **автоматическое всплывающее окно с видео при нажатии
  кнопки открытия** — контроль проезда (через browser_mod).
- **v1.1.0: кнопка «Обучить»** (значок камеры) — отправляет текущий кадр в базу
  «своих» машин аддона [ha-smart-access](https://github.com/NoIDXMV6/ha-smart-access);
  шлагбаум начинает открываться этой машине автоматически.

```
ha-barrier-cards/
├── cards/
│   ├── amvideo_govorovo.yaml          # А.М.Видео: 1 шлагбаум (деревня Говорово)(15072)
│   └── egds_lesnaia.yaml              # ЕГДС: Ул. Лесная · Шлагбаум №1 (Камера №1)
└── automations/
    └── open_barrier_video_popup.yaml  # авто-открытие видео при нажатии «Открыть»
```

## Вариант 1. Карточка с видео и кнопкой (без дополнительных компонентов)

1. Откройте панель (Обзор) → **Изменить** (карандаш) → **Добавить карточку** →
   в самом низу списка **«Вручную»**.
2. Удалите заготовку редактора, вставьте содержимое нужного файла из `cards/`
   целиком (с `type: picture-elements` в первой строке) → **Сохранить**.
3. Каждый шлагбаум — отдельная карточка.

Что получится:

- **видео идёт вживую постоянно** (`camera_view: live`): нажали «Открыть» —
  и сразу видите шлагбаум;
- круглая кнопка **Открыть** справа внизу отправляет команду
  (`amvideo.open_barrier` / `egds.open_barrier`), перед нажатием спрашивает
  подтверждение;
- кнопка **развернуть** слева внизу открывает живое видео в отдельном окне
  (на телефоне — почти на весь экран);
- подпись внизу — состояние шлагбаума (Закрыто / Открывается / Открыто).

## Вариант 2. «Нажал Открыть → видео открылось само» (нужен browser_mod)

Хотите, чтобы после нажатия кнопки живое видео всплывало отдельным окном
и закрывалось само через 90 секунд:

1. Установите **browser_mod** через HACS: HACS → поиск «browser_mod» →
   **Скачать** → перезапустите Home Assistant → обновите страницу (Ctrl+F5).
2. На каждом устройстве, где нужно всплывающее окно (компьютер, планшет,
   телефон в приложении HA): **Настройки → Устройства и службы → Browser Mod →
   Настроить** → задайте имя браузера (например, «ноутбук», «телефон»).
3. Создайте автоматизацию: **Настройки → Автоматизации и сценарии →
   Создать автоматизацию → ⋮ → «Изменить в YAML»** → вставьте содержимое
   `automations/open_barrier_video_popup.yaml` → **Сохранить**.

Карточки из Варианта 1 менять не нужно: автоматизация следит за вызовами
`amvideo.open_barrier` и `egds.open_barrier` — откуда бы ни была нажата
кнопка открытия, на всех устройствах с browser_mod всплывёт окно с живой
камерой нужного шлагбаума. В окне есть кнопка «Открыть повторно» — удобно
пропустить следующую машину.

## Как проверить ID сущностей

Камеры в примерах подтверждены. Кнопки и cover сверьте со своими:

**Инструменты разработчика → Состояния** → в фильтре наберите `otkryt` —
скопируйте точные имена вида
`button.<...>_otkryt` и подставьте их в карточку (в двух местах: `entity`
элемента и `target.entity_id`). Аналогично cover — фильтр `shlagbaum`.

Также: Настройки → Устройства и службы → интеграция А.М.Видео / ЕГДС →
устройство шлагбаума → сущности.

## Примечания

- Повторное открытие ограничено интервалом ~20 секунд (штатная защита
  интеграций от дребезга) — при частых нажатиях команда просто
  игнорируется сервером.
- Камера А.М.Видео отдаёт настоящий видеопоток (MPEG1-TS over WebSocket →
  MJPEG), камера ЕГДС собирает «живую» картинку из снимков (~1 кадр/с).
- Если Home Assistant старше 2024.8: в YAML замените
  `action: perform-action` / `perform_action:` на
  `action: call-service` / `service:`, а в автоматизации
  `triggers:` → `trigger:` и `actions:` → `action:`.
- Окно browser_mod появляется на всех устройствах с настроенным browser_mod;
  ограничить конкретным устройством можно через параметр `target` сервиса
  `browser_mod.popup` (см. документацию browser_mod).
